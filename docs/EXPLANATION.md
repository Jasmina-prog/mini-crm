# Как работает система (для руководителя)

**Что это.** Небольшая CRM, где можно вести объекты (например, стройки или здания) и задачи по ним. В системе две роли.

- **Постановщик** создаёт объекты и задачи и назначает исполнителя. Когда исполнитель сдаёт работу, постановщик её принимает или возвращает на доработку с комментарием.
- **Исполнитель** видит только свои задачи. Он берёт задачу в работу и отправляет её на проверку.

**Путь задачи:**

Новая → В работе → На проверке → Принята

С проверки задачу можно вернуть «На доработку», после чего исполнитель снова берёт её в работу. Перескочить через шаг нельзя: например, исполнитель не может сам отметить свою задачу принятой. Каждому пользователю система показывает только те кнопки, которые ему сейчас доступны.

**История.** Каждая смена статуса записывается в историю: кто, когда, из какого статуса в какой и с каким комментарием. Историю видят обе стороны. Изменить или удалить записи не может никто: ни сотрудник, ни постановщик, ни администратор через служебный доступ.

**Почему данные защищены.** Правила «кто что видит и что может делать» проверяет сама база данных, а не только экран приложения. Если сотрудник попробует обойти интерфейс и обратиться к серверу напрямую, база всё равно не отдаст ему чужие задачи и не позволит нарушить порядок статусов. Мы проверили это специальным скриптом: он пытается сделать 25 запрещённых действий, и все они отклоняются.

**Доступ.** Зарегистрироваться самостоятельно нельзя, учётные записи заводит администратор. Секретные ключи хранятся отдельно и не попадают ни в приложение, ни в репозиторий с кодом.
